# 实验设计与量化结果

更新日期：2026-11-05

## 1. 实验目标

1. 验证统一事件存储在本地 JSON 下的写入/查询开销；
2. 验证本地情绪词库在小型标注样例上的关注识别能力；
3. 为答辩提供可复现的测量方法，而不是主观描述。

## 2. 实验环境

| 项目 | 配置 |
|---|---|
| 操作系统 | Windows 11 |
| Python | 3.12（项目要求 3.10+） |
| 存储 | 临时目录 JSON 文件，原子写入 |
| 并发 | 单线程，无并发请求 |
| 测量工具 | `time.perf_counter()`，200 次迭代 |

## 3. 事件存储基准

命令：

```powershell
python scripts/benchmark_events.py --iterations 200
```

结果（2026-11-05 本地）：

| 操作 | 样本 | 平均 | P50 | P95 | 最大 |
|---|---:|---:|---:|---:|---:|
| `create_event`（含落盘） | 200 | 4.087 ms | 4.046 ms | 6.656 ms | 8.159 ms |
| `query_events`（每次最多返回 50 条） | 200 | 1.147 ms | 1.166 ms | 2.128 ms | 2.678 ms |

解释：

- 创建包含字段校验、去重、JSON 序列化与原子替换，4 ms 量级满足演示与单机使用；
- 每次写入后查询一次，事件库由 1 条增长至 200 条。表中查询耗时汇总了这 200 次请求。
- 事件上限 2000 条，规模继续增长时应迁移 SQLite 或增加索引。

## 4. 情绪词库小样本评估

[基准脚本](../scripts/benchmark_events.py) 内置 10 条人工标注样例，包含 3 条无关注（`none`）、4 条 `watch`、3 条 `urgent`。其中 1 条无关注样例含否定语境。下表只统计本地词库在这 10 条样例上的结果。

| 指标 | 结果 |
|---|---:|
| 样本数 | 10 |
| 关注等级完全匹配率 | 10/10（100%） |
| 关注识别精确率 | 1.000 |
| 关注识别召回率 | 1.000 |

样例来自词库覆盖的表达，适合核对规则链路和回归。真实儿童语料的准确率仍待用独立、脱敏的标注样本测量，本地词库和模型模式应分别统计。

## 6. 局限性

- 单机、无并发，未覆盖多用户同时写入；
- JSON 全量写入，事件接近 2000 条时性能会下降；
- 情绪样例规模小且与词库同源，缺少独立评估样本；
- 真实设备、网络和模型 API 的时延需现场测量。
