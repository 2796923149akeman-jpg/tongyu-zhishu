# 开题报告与当前实现对照

2026-11-05 · 核对《童域智枢-开题报告》§3–§9，以 `main` 分支代码、自动化测试和验证记录为依据。

## 六项建设能力

| 开题承诺 | 当前实现 | 待完成或待验收 |
| --- | --- | --- |
| 开放式模型接入（§3.1、§5.2） | 管理员可设置兼容 API 地址、模型和密钥，密钥脱敏返回并校验 URL 协议；ESP32 由小智后端调用模型。角色提示词保存在语音后端配置中。 | 管理页缺少独立的连接测试入口和提示词、请求超时编辑项。 |
| 对话与双模式情绪分析（§5.3） | 消息持久化，可按会话、日期和设备回看并搜索；本地词库考虑否定语境，模型模式失败可回退并记录分析来源。关注结果进入对话页、日报，并自动生成 `dialogue_attention` 待处理事件（按会话、关注等级、情绪标签和固定时间桶去重，默认桶宽 600 秒，事件只保存通用说明和会话编号）。管理员可把消息关联到具体孩子，家长在日报中按权限查看。 | 事件详情暂未直接跳转到对应会话；情绪事件的处置闭环和对话证据定位仍可加强。 |
| 视觉与环境巡护（§5.1、§5.4） | 显示采集时间、连接和过期状态。监控请求读到 RDK 摔倒、斗殴告警时自动建事件并尝试抓拍；后台每 30 秒读取传感器，对连接断开、数据过期、eCO₂/TVOC 超限自动建事件并去重。监控页告警可跳转事件页，人物估算为可选实验功能。 | 关闭监控页时后台仍会读取传感器并建事件，但没有独立于 Dashboard 的采集守护进程；真实阈值仍需按现场设备标定。 |
| 统一事件处置与提醒（§5.4、§6.1） | 支持事件编号、去重键、抓拍、待处理／已处理／误报、备注和处理历史；老师可按姓名关联参与学生（摔倒 1 人、斗殴至少 2 人，同名用 `姓名@学号`）；家长事件箱、截图授权和家长日报按绑定学生隔离；监控页轮询提示新事件；配置 `ALERT_NOTIFY_URL` 后摔倒/斗殴事件会异步推送播报并记录成功或失败；抓拍结果记录 `snapshot_status`/`snapshot_error`，管理员可重新抓拍。 | 播报通道使用通用 HTTP 接口，真实 ESP32 TTS 网关仍需现场联调。旧 RDK 的视频流回退帧采自 Dashboard 处理时刻，不能视为检测瞬间的帧。 |
| 名单与体温（§5.5） | 名单导入、按编号登记、测量来源、复测、CSV 导出、实时红外确认和设备令牌自动入库均已接入；学生支持昵称显示，家长端不直接暴露名单姓名。 | 已完成模拟输入与接口测试。当前版本仍需用真实设备验证采集、登记和复测全链路。 |
| 当日日报与维护日志（§5.5） | 按事件发生日汇总，以最新状态展示。提供班级／全园日报、体温趋势、浏览器打印或另存 PDF；家长日报按孩子隔离。 | 缺少园方日报的结构化 CSV 导出和可按事件编号查询的维护日志。 |

## 账号与权限（开题未展开，当前扩展）

- 注册账号进入 `pending`；管理员在账号管理页分配 `viewer`、`parent`、`merchant` 或恢复 `pending`。
- 家长账号绑定 1–20 名学生，并单独控制事件、截图、日报、对话四项权限；商家账号只能读取环境传感器字段。
- 业务写接口仅限管理员，需同源与 CSRF；登录有频率限制；密钥、儿童名单、抓拍和对话文件均被 Git 忽略。

## 安全、存储和维护（§4.3、§6.3）

有角色权限、密钥脱敏、业务文件忽略规则和原子写入。对话支持删除，事件、消息有保留条数上限。业务编排主要集中于 Dashboard 服务，五类业务记录经独立 JSON 仓储持久化。儿童数据的统一保留期限和批量清理仍待完善。SQLite 属于开题备选方案。

## 交付验证缺口

- **功能联调。** 现有自动化和浏览器验证覆盖模拟设备和接口。真实设备联调记录模板见 [真实设备联调记录](DEVICE_VALIDATION.md)，需要在答辩前用 ESP32、RDK X5 和 STM32 填写实测结果，明确设备、网络和模型配置；尤其需要验证 RDK `/snapshot` 抓拍链路。
- **重构效果。** 缺少按 §7.2 采集的同输入前后对照、告警到界面的延迟分布，以及人工标注样例上的两种情绪模式误报和漏报统计。
- **演示材料。** 仓库包含运行说明、接口说明和验证记录，并提供 [42 秒模拟演示视频](https://github.com/2796923149akeman-jpg/tongyu-zhishu/releases/tag/course-demo) 和 [现场演示流程](DEMO_SCRIPT.md)。
